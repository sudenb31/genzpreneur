APA YANG BERUBAH
- Menu Kondisi Awal di /app/kondisi-awal, opsional dan dapat diisi sebagian.
- Empat bagian: tujuan/kemampuan, penerima/contoh, penawaran/pengalaman, waktu/kendala.
- Jawaban belum tahu/belum pernah dan contoh fiktif/publik diperbolehkan. Tidak ada upload baru atau pekerjaan gratis wajib.
- Enam kebutuhan dipetakan terpisah, dengan aturan A–E dan satu pertanyaan klarifikasi saat informasi penting tidak selaras/belum jelas.
- Hasil menampilkan bekal, yang belum jelas, alasan rekomendasi, tombol pekerjaan, ubah jawaban dan pilihan titik masuk lain.
- Assessment minat tetap terpisah. Jawaban minat tidak dijadikan skor kesiapan kerja.
- Dashboard/Misi menghormati pilihan tahap manual dan melanjutkan draf yang sudah ada. Memilih tahap tidak menyelesaikan tahap lain.
- Cek singkat bekal pada tahap Misi lanjutan, tanpa penguncian baru.
- Ringkasan baca kondisi awal di Peserta & Paket, dimuat ketika admin membuka satu peserta.
- Logo resmi dan tombol sidebar tiga garis dari revisi lokal sebelumnya ikut disertakan. Sidebar dapat ditutup ke kiri lalu dibuka kembali; ruang konten melebar dan preferensi disimpan di browser.

YANG TIDAK DIKLAIM
Ini rekomendasi berdasarkan jawaban peserta, bukan sertifikasi skill atau review mentor.
Contoh yang dilaporkan tersedia dibedakan dari teks/tautan yang benar-benar diberikan. Kualitas/keamanan tautan tidak diperiksa otomatis.
Belum ada alur yang bisa memberi status ditinjau mentor; membuka ringkasan admin tidak menghasilkan status tersebut.
Tidak ada janji review personal, batas waktu respons, pelanggan atau penghasilan.
Tidak ada kiriman data peserta ke Heybinder atau layanan AI baru.

SEBELUM RILIS PRODUKSI
1. Tinjau docs/AUDIT-KONDISI-AWAL.md dan perubahan sumber.
2. Di lingkungan uji yang mempunyai Java sesuai kebutuhan Firebase CLI, jalankan npm ci, npm run typecheck, npm test, npm run test:rules dan npm run build. Emulator menggunakan proyek demo-genz; jangan arahkan tes ke database produksi.
3. Pada staging/Firebase proyek uji, masuk sebagai dua akun peserta terpisah dan admin. Simpan kondisi awal akun A, muat ulang, lanjutkan pengisian; akun B tidak boleh membaca/menulis progres A, admin hanya membaca A. Mentor biasa tidak memperoleh akses tambahan.
4. Periksa catatan Misi, d1–d7, task dan pelajaran akun uji sebelum/sesudah mengubah kondisi awal dan titik masuk. Semuanya harus tetap utuh.
5. Uji A–E, belum tahu, contoh tanpa lampiran, penawaran tanpa contoh dan pengalaman yang belum jelas kaitannya. Saran tidak boleh terlihat sebagai verifikasi kemampuan.
6. Ubah jawaban dan pilih titik masuk manual. Buka Misi, pastikan tahap sebelumnya tidak otomatis dicentang. Coba cek bekal tahap lanjutan.
7. Pastikan peserta lama dapat langsung melanjutkan Misi tanpa mengisi ulang kondisi awal. Tes mobile, keyboard, error jaringan dan buka/tutup sidebar.

CARA MEMASANG JIKA REVISI SUDAH AKAN DIGUNAKAN
1. Ekstrak ZIP di Downloads, buka folder genz-preneur-os di dalamnya.
2. Upload seluruh ISI folder proyek ke root repo GitHub/branch yang benar, bukan file ZIP atau folder pembungkus baru. Sertakan src, public, docs, tests dan file konfigurasi.
3. Jangan menimpa environment variables Firebase dengan nilai contoh. Tidak diperlukan variabel baru untuk fitur ini.
4. Commit changes memicu deployment bila branch terhubung Vercel. Karena langkah itu bisa mempublikasikan perubahan, lakukan setelah review dan pemeriksaan staging selesai.
5. Di Vercel Deployments, cocokkan commit lalu tunggu status Ready. Periksa URL deployment dan domain yang aktif. Gunakan hard refresh bila cache menampilkan versi lama.
6. Firebase Rules tidak berubah: tidak perlu Publish ulang. Bila proyek produksi belum memakai Rules baseline, periksa masalah itu terpisah; jangan melemahkan Rules untuk mengatasi error.
